# 验收矩阵

| ID | 可测验收条件 | 验证方法 |
|---|---|---|
| AC-01 | 默认专家数 4；空议题/非法范围有中文提示 | UI/E2E |
| AC-02 | 1 主持人 + 指定 N 专家，背景/立场至少两类实质差异 | fixture/API |
| AC-03 | 未确认启动返回冲突，确认后才 running | API 集成 |
| AC-04 | 有主持开场、引导和自然语言总结 | E2E |
| AC-05 | speaker 序列非静态轮询，至少一次回应/反驳 | 受控编排 |
| AC-06 | 每条公开发言符合 1–2 句和字符上限 | 单元/集成 |
| AC-07 | 专家卡状态与事件一致，页面无思维链/内部事件 | SSE/UI |
| AC-08 | 结束前更新过共识/分歧，每项关联 ≥1 Transcript 证据 | 集成 |
| AC-09 | Transcript 持久化人物、头衔、颜色、文本、顺序/时间，刷新一致 | DB/API/E2E |
| AC-10 | SSE 有递增 ID、discussion_id、类型、时间，Last-Event-ID 可补齐 | SSE 集成 |
| AC-11 | 并行 A/B 讨论的查询、事件、发言和洞见不交叉 | 并发/E2E |
| AC-12 | 构建物、响应与 Git 历史无 API Key，密钥只从环境读 | 安全检查 |
| AC-13 | 中文 UI；三类视口下各面板独立滚动 | Playwright |
| AC-14 | 空库初始化得 Schema 和 ≥5 套样例，重复运行有确定行为 | 初始化集成 |
| AC-15 | 创建→确认→实时讨论→总结 E2E 通过；模型超时/格式错误可恢复 | Playwright + mock LLM |

通过门槛：AC-01~15 全部通过；失败必须有根因、范围化修复和回归证据，不能以“模型通常正确”替代测试。

## 阶段 3 验证范围

当前自动化测试使用独立临时 SQLite 和 Fake LLM，覆盖嘉宾幂等生成、确认/启动/停止、动态非轮询顺序、发言及事件顺序、洞见证据归属、SSE 补读、双讨论隔离与模型故障。前端通过 TypeScript/生产构建。真实模型结果以 `docs/prompts/03-tdd.md` 中的实际烟雾测试记录为准；本矩阵不将 Fake LLM 测试等同于真实模型全链路验收。
