# 产品需求文档（PRD）

## 产品目标
AI Panel Studio 是中文本地 Web MVP：用户输入议题和专家人数（默认 4），确认由 AI 生成的主持人与专家阵容后，观看一场有真实观点交锋的圆桌讨论。结果包括可追溯 Transcript、实时共识/分歧与自然语言总结；目标不是固定顺序的多角色复述。

## 用户画像
| 用户 | 痛点 | 收益 |
|---|---|---|
| 知识工作者/研究人员 | 时间有限、难横向分析 | 快速多角度分析 |
| 产品/决策人员 | 需验证假设与风险 | 不同立场审视方案 |
| 教育/内容创作者 | 需要可回放对谈素材 | 获得结构化讨论 |

## 需求清单与追踪
| ID | 需求 | 优先级 | 验证 |

| FR-01 | 首页列出讨论并可新建/进入 | Must | 多讨论可独立查看 |

| FR-05 | 主持人开场、引导、追问、串联、总结 | Must | 生命周期可观察 |
| FR-06 | 专家按上下文补充、反驳、申请发言，非固定轮询 | Must | 调度测试 |
| FR-07 | 单次公开发言 1–2 句 | Must | 服务端长度校验 |
| FR-08 | 专家卡显示真实待命/准备/发言状态和公开关注点，不暴露思维链 | Must | SSE/UI 一致 |

## 业务流程
```mermaid
flowchart LR
A[输入议题/专家数]-->B[生成候选阵容]-->C{用户确认?}
C--否：调整/重生成-->B
C--是-->D[初始化讨论与 SSE]-->E[主持人调度行动]-->F[生成并校验发言]
F-->G[持久化 Transcript/事件]-->H[增量提炼洞见并广播]-->I{结束?}
I--否-->E
I--是-->J[主持人总结并归档]
```

## 核心规则
1. 仅确认阵容后进入运行态；每场讨论独立 ID、上下文和事件流。
2. 调度依据最近发言、观点覆盖、冲突信号、参与均衡、冷却和剩余轮次，不按静态名单轮询。
3. 内部选人/举手为运行事件，不能作为公开 Transcript。
4. 共识/分歧必须关联发言证据；无证据则不创建或标待验证。
5. 模型输出经 Schema、角色、长度和引用校验；失败有限重试后进入可恢复错误状态。

## MVP 边界
包含单机 SQLite、多讨论、SSE、OpenAI-Compatible 后端适配、阵容确认、样例数据与核心自动化测试。不含登录/权限、音视频、协同编辑、微服务、复杂队列和生产级监控。
